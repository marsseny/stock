# AGENTS.md

## Architecture
SPA: Vite + React 19 + React Router 7 (`BrowserRouter`), TypeScript, a single hand-written stylesheet `src/styles/global.css` (no Tailwind). Hosting: **Cloudflare Pages** (`wrangler.toml`, output `dist/`). Pages project settings MUST be: build command `npm run build`, output directory `dist` (otherwise raw source is served and /api is missing). Backend: platform-independent Web `Request → Response` handlers in `src/server/`, bundled by `npm run build` (rolldown) from `cf/worker.ts` into `dist/_worker.js` (Pages advanced mode: `/api/<route>` → `routes[route]` with `setServerEnv(env)`, everything else → static assets with SPA fallback). No `functions/` dir: it is ignored when `_worker.js` exists. Netlify is no longer used — do not add Netlify config or paths. Services: Supabase (DB + auth), Whop (payments), Cloudflare R2 (private ZIPs).

## Key directories
- `src/data/products.ts` — mock catalog generator; the only source of product data. Pages use its exported helpers (`PRODUCTS`, `getProduct`, `FEATURED`, `ALL_TAGS`, `formatPrice`), so swapping in real data only touches this module.
- `src/components/VideoPreview.tsx` — owns playback. Mute state is NOT local: it comes from `src/store/sound.ts` (global, sessionStorage-backed), so sound turned on in one preview stays on everywhere until the visitor mutes it. If the browser refuses unmuted autoplay (no user gesture yet), the preview falls back to muted locally (`blocked`) without changing the global preference. On cards the sound toggle (`preview__sound`) appears only while `is-playing`. `controls` (product page) renders the `.player` bar: play/pause, range-input timeline (`--pct` drives the fill), time, sound; clicking the video toggles pause. Placeholders simulate a timeline from `product.duration`. Pass `sound={false}` for static thumbnails (My Purchases cards).
- `src/data/specs.ts` reads `src/data/product-specs.csv` via Vite `?raw` (comma or semicolon, quoted values) into `SPECS_BY_SLUG`; `products.ts` attaches it as `product.specs`. The product page shows those rows verbatim and in order, falling back to the default rows built from product fields.
- Reviews: NO mock or generated reviews/ratings, ever (fake reviews and star ratings are illegal: FTC 16 CFR 465, EU UCPD Annex I 23b/c, UK DMCC Act). Products have no `rating`/`reviewsCount` fields; `src/lib/useProductReviews.ts` shows only `/api/reviews` rows; count 0 → "No reviews yet" with a half-transparent white star (`.rating--empty`) instead of the lime one. All reviews are equal (no "Verified buyer" label). `src/components/Reviews.tsx` renders the panel (first 4) and a `<dialog>` with all reviews. `sales` is kept only for "popular" sorting. In `products.ts` the removed `rating` draw is replaced by a bare `rand()` before `preview.hueA` so the seeded sequence (slugs) stays stable — keep it.
- `src/components/ProjectDetails.tsx` + `src/data/details.ts` — description block under the product video: bento grid (summary tile + feature tiles), "What's included" (no "N scenes · N categories" caption; category tabs with counts only when there are 2+ groups → 1–8 rows of 16:9 scene thumbs, 3 per row (`ceil(n/3)` rows, max 8; beyond 24 scenes each row scrolls horizontally), no scene numbers on thumbs), small tags. Content is per project in `src/data/details/<slug>.json` (loaded via `import.meta.glob`); every key falls back to defaults in `details.ts`. Featured-only features (MotionBro, auto-resize, duration control, elements count, updates/license/support) show for `tier === 'featured'` unless `showFeatured`; standard features show for AE/PR categories only. Tile order is tuned for a 4-column dense grid (lg 2×3, md 1×3, stat 1×6, sm 1×1) — keep it gap-free when changing defaults. Bento responds via container queries. Owner guide: `docs/DESCRIPTION-GUIDE.md`.
- Product page right column `.product__side` is sticky; it becomes static while the reviews panel is open so a tall column can scroll.
- `src/components/ProductCard.tsx` — the card media is a `div`, not a link: a full-size `.card__hit` link sits underneath, the preview sits above with `pointer-events: none`, and only the sound button re-enables pointer events. This avoids nesting a `<button>` inside an `<a>`.
- `src/App.tsx` + `.backdrop*` in CSS — animated background: blurred conic-gradient rings and an orb slowly rotating (CSS transforms only; disabled with `prefers-reduced-motion`).
- `docs/` — content-preparation guide (Russian) and product data templates for the owner.

- `src/server/` — `env.ts` (reads process.env / Deno / globalThis / `setServerEnv`), `http.ts` (CORS, errors), `r2.ts` (presigned R2 links, Web Crypto SigV4), `supabaseAdmin.ts` (service role, `purchases` helpers), `whop.ts` (payment lookup over fetch, webhook signature via Web Crypto), `handlers/*`. `src/data/whopPlans.ts` must stay free of Vite-only imports because the server bundles it.
- `supabase/schema.sql` — `purchases` and `reviews` tables, `generate_license_key()`, RLS (select own e-mail; writes only via service role). E-mails are stored lower-cased.

- Purchase flow (no cart; Whop embedded checkout pays one plan at a time): `BuyNowButton` (product cards on Home/Browse + product page) → `CheckoutModal` (portal, stages `details → pay → verifying → ready | error`) → `src/lib/api.ts`. **No account is required**: `details` asks for a typed e-mail and a promo code (there is NO Google / OAuth sign-in anywhere). `pay` mounts Whop Elements (`@whop/elements` + `@whop/elements-react`: `WhopElements` → `Checkout plan` → `CheckoutElement buyerEmail lockBuyerEmail`), SDK loaded once via `loadWhop()`; `onComplete` gives `paymentId` (`pay_…`) which is sent to `/claim-download` as `receiptId`. The legacy `@whop/checkout` iframe (`whop.com/embedded/checkout/…`) was removed: Whop now answers it with "This checkout is no longer available" for every plan. Elements theme accepts only named accent colours (`lime`), not hex. `/claim-download` verifies the receipt with Whop and stores the purchase under the typed e-mail (a valid Bearer token wins; fresh webhook rows stored under Whop's e-mail are re-assigned). A 100% promo skips `pay`: `/claim-free` (server re-checks `FREE_PROMO_CODE`, default `TEST100`; `FREE_PROMO_DISABLED=true` turns it off) records the e-mail and returns the ZIP link at once. `src/lib/promo.ts` owns codes (`NEXT15` 15%, `VIP20` 20%, `TEST100` 100%); never list valid codes in error messages. The last checkout e-mail is remembered in localStorage `fh_checkout_email`. Google sign-in was removed (v19) together with `pendingCheckout.ts` and the OAuth `authorize` route of the auth proxy; a buyer already signed in to My Account by e-mail link sees "Signed in as …".
- Promo codes are NEVER pre-filled from the account or purchases. `PromoCodeField` (low-key "Have a promo code?" link → input → applied chip) is used on the product page and in the checkout. An applied code is kept 15 min in localStorage `fh_promo_applied` (`{code, exp}`; TEST100 never stored) and cleared after an order; the legacy auto-saved `fh_active_promo` is deleted on load.
- Browser Supabase client: `src/lib/supabase.ts` exposes `loadSupabase()` (memoized promise) and `useSupabase()` (hook `{ supabase, ready }`) — there is NO synchronous `supabase` export any more. Config: build-time `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY`, else runtime `GET /api/public-config` (`src/server/handlers/publicConfig.ts`, server env `SUPABASE_URL` + a public key found by `src/server/publicKey.ts`, which accepts several names and rejects secret keys), else — when the server has no public key but has `SUPABASE_SERVICE_ROLE_KEY` — proxy mode: the client is created with URL `/api/sb` and a placeholder key, and `src/server/handlers/authProxy.ts` forwards an allow-list of end-user Auth endpoints (otp, verify, token refresh/pkce, user, logout, settings; no OAuth `authorize`). REST is never proxied: purchases come from `GET /api/my-purchases` (server, matched by the verified e-mail). Workers/servers must route with `resolveRoute(path)` (prefix `sb/auth/v1/`), not `routes[...]`. The load starts at module import so the magic-link hash is consumed early; `flowType: 'implicit'` so a link opened on another device still works. `initialLinkError` reports `#error_code=otp_expired` etc. to `AuthForm`.
- Free vs paid: purchases with `whop_receipt_id` starting `free_` (from `/api/claim-free`) are free files (`isFreePurchase`). Loyalty promos (`promoForPurchases` in the browser, `nextPromoFor` + `countPaidPurchasesByEmail` on the server) count paid purchases only; `nextPromoFor(0)` returns an empty code.
- My Account (`src/pages/Account.tsx`, route `/account`; renamed from My Purchases): sign-in is ONLY a magic link (`AuthForm`: e-mail → `signInWithOtp` with `emailRedirectTo: <origin>/account`; `detectSessionInUrl` picks the session up). There is no Google sign-in. Page order: payment-return notice → auth form / welcome block (`Welcome`, thanks the customer) + promo banner (paid buyers only) + purchases (download, license, `RateProject` stars → short review → `/api/reviews` → product page) with a Log out button → Help & FAQ + "Ask a question" (`/api/contact`) and Service rules → "Fresh projects" (4 newest `PRODUCTS` by `createdAt`, `ProductCard`). Off-site payments (3-D Secure, bank pages) return to `/account?product=<slug>&payment=pay_…&status=succeeded|failed|canceled` (`returnUrl` on `<Checkout>`); `PaymentReturn` claims a succeeded payment via `/claim-download` using the e-mail from localStorage `fh_checkout_email`, shows the license + ZIP link, and explains failed/canceled. `/api/contact` sends the question via Resend (`RESEND_API_KEY`, `CONTACT_FROM_EMAIL` on a verified domain, `CONTACT_TO_EMAIL` default client@nuovamotion.com), Reply-To = buyer, honeypot field `website`. Previously: RLS `purchases_select_own` shows rows whose e-mail equals the JWT e-mail, so guest purchases appear after signing in with the same address. Re-download → `/get-download-url` (fresh presigned R2 link).
- `src/server/r2.ts` signs R2 links with SigV4 over Web Crypto (no AWS SDK, Workers-compatible); verified against boto3.
- Reviews: table `reviews` (unique `email, product_slug`, RLS with no policies — only the service role). `/api/reviews` (GET `?slug=` public, GET `?mine=1`, POST upsert; POST requires a PAID purchase — `hasPaidPurchase`, receipts `free_…` don't count; My Account hides stars on free files). Display name is derived server-side (`shortName`: "Maya R."). Product page uses `src/lib/useProductReviews.ts` (real reviews first, then mocks; rating/count combined). `CopyButton` is the shared copy-with-"Copied!" control.
- Frontend must stay host-agnostic: API calls use `${import.meta.env.VITE_API_BASE_URL || '/api'}/<route>` only; never reference the hosting provider in `src/` or `api/`.

## Conventions / decisions
- Brand: **Nuova Motion** (domain nuovamotion.com). Logo = `src/components/Logo.tsx` (`LogoMark` lime tile with a slanted "N" + wordmark "nuovamotion.com"), same drawing as `public/favicon.svg`. Internal storage keys keep the old `fh_` prefix on purpose so saved promos / pending checkouts survive the rename. `wrangler.toml` `name` is left as is (deploy config).
- No progress bar on card previews (removed on request). The only timeline is the scrubbable `.player__timeline` on the product page.
- Product cards (Home / Browse / lists) show the price WITHOUT the tax hint and without "by author". On the product page (and in the checkout) prices are followed by `TaxHint` (`src/components/TaxHint.tsx`): a small "+ tax ⓘ" chip whose tooltip (hover / focus / tap) says the buyer's VAT / sales tax is added at checkout. The Buy now button does not repeat the price.
- App badges use `AppBadge` (`ProductCard.tsx`): short code ("AE") that expands to the full category label on hover. Both labels are absolutely positioned and measured (`--badge-w-short/full`); only `width` animates + labels cross-fade — do not go back to `max-width` transitions (they looked jerky). On cards it is a link to the product so clicking it still opens the item.
- Shop dropdown / mobile menu / nav pill are near-opaque dark glass (readability over previews) — do not make them translucent again.
- Home hero copy must not mention product counts (the catalogue is small and curated).
- All previews are 16:9 and look identical regardless of tier; packs are distinguished only by the "Pack · N items" badge (the old stacked-card look was removed on purpose).
- No play-button overlay on previews.
- `preview.hueA/hueB/variant` only drive the placeholder; make them optional when real products with `video`/`poster` are added.

## Hosting (test stand)
- Naive app `framehaus` (fullstack, runs on Vercel): `vercel.json` (SPA rewrite), `api/*.ts` = serverless entry points (default export + GET/POST/OPTIONS) over `src/server/`. `cf/worker.ts` → `dist/_worker.js` + `wrangler.toml` is the Cloudflare Pages entry; `api/*.ts` run on the Edge runtime (`config.runtime = edge`).
- Browser `VITE_*` values live in `public.env` (read by `vite.config.ts`); server secrets are app secrets (SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, WHOP_API_KEY, WHOP_WEBHOOK_SECRET, R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_PRIVATE_BUCKET_NAME).
